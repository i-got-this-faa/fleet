# Fleet Writing Style

Use these rules for Fleet documents and for text that Radhey asks to send.
These rules apply the general principles of ASD-STE100 Issue 9. They do not
claim formal certification against the complete controlled dictionary.

## Words

- Use one word for one meaning.
- Use the same term each time you refer to the same item.
- Use common words when they keep the technical meaning.
- Keep project names, command names, file names, and code terms unchanged.
- Define a new technical term when its meaning is not clear from the context.
- Do not use jargon only to make the text sound formal.

## Sentences

- Use the active voice when you know the actor.
- Put one main instruction in each sentence.
- Keep sentences short. Split a sentence when it has more than one main idea.
- Put a condition before the action when the condition must occur first.
- Use positive instructions when they are safe and clear.
- Use lists for a sequence or for a set of checks.

## Procedures

- Start each step with an action verb.
- Give one action in each numbered step.
- Put the expected result after the action.
- Put warnings before the action that can cause harm.
- Do not mix background information with an action step.

## Reports

- State the result first.
- Separate facts from inferences.
- Name the evidence for an important claim.
- State a test limit directly.
- Do not use an implementation inventory as the opening summary.

## Final Check

- Remove repeated information.
- Replace vague words such as `thing`, `stuff`, or `works` with a precise term.
- Check that each pronoun has a clear noun.
- Check that each sentence has one clear purpose.
- Check that a reader can act without reading the sentence two times.
